# 2026-11-18 证据失误三条（lead 侧记账）

**这份文件记的不是插件的缺陷，是「我做判据」时出的错。** 三条都在同一天里真实发生过，
且每条**都曾经被当成通过**——直到被独立核对打掉。

写下来的原因：这些错的形态都不是「不会写代码」，而是**证据链在某一环没有回显它声称匹配到的东西**。
下一次（包括下一代交接）遇到同类判断时，先读这里。

## 1. TD 关闭状态扫描器：把**下一条** TD 的关闭语记到了上一条头上

**事实**：B3 派工单 §〇 写了「TD-M6、TD-M7 已关闭（条目里写着状态：已关闭（2026-11-18））」。
`ARCHITECTURE.md` 里**从来没有这两句**——B3 的实现方 DSH 逐条核后指出这一点，我复核确认：
M6 / M7 的条目至今没有关闭标记，两条的「退出条件」都还是活的。

**扫描器当时的输出**（原文照抄）：

```
TD-M1   未标记关闭
TD-M6   已关闭
TD-M7   已关闭
TD-M4 无
TD-M13  未标记关闭
```

**根因两处，缺一不可**：

1. 那份 `ARCHITECTURE.md` 的 TD-M7 表格**两行粘连成一行**：
   `| 为什么现在不动 | … || 退出条件 | 复用 task-alignment 的 taskTerms… |`
   （同一段里还有 `### ### TD-M7` 双标题）。粘连已在 `4798e7d` 修掉。
2. 我的扫描器按「下一个 `### ` 标题」切段。粘连让切段**失效**：M6 的窗口越过了那个假标题，
   M7 的窗口也一样，于是下一节 TD-M12 的 `> **状态：已关闭（2026-11-18）。**` 一行
   **同时落进 M6 与 M7 两个窗口**——两个「已关闭」都是它。

**后果与为什么贵**：这条错判直接进了派工单，形式是「不要重新实现这些，它们已经关了」。
如果 DSH 照做，两项真 TD 会被**永久当成已关闭**而不做——而这正是我最常警告别人的那个形态
（判据说谎）。它没照做，是因为它自己去核了文件；**把我救回来的是它的核对，不是我的判据。**

**纪律（新，已写入下一批派的验收要求）**：凡扫描器给出的状态判定，**必须回显它匹配到的
那一行原文**（含行号）。只回显「已关闭」三个字的状态报告**不算证据**——
它没法区分「这条的关闭语」和「邻居的关闭语」。

## 2. 临时备份名不带原文件名 ⇒ 恢复错文件 ⇒ 读到假读数

**事实**：给 graft 做「未声明导出」探针时，我把 `src/index.ts` 备份成 `%TEMP%\gidx.ts.bak`，
随后把 `gidx.ts.bak` 恢复到 **`src/core/task-position.ts`**（目标写错了）。

**连锁后果**（这条错的价值在于它不是一步失败，而是**静默地**给出一个可信的读数）：

1. `index.ts` 的内容被写进了 `task-position.ts`；
2. `build` 因此**静默失败**（我没看它的退出码）；
3. `verify-bundle` 于是读到**旧产物**，报告「201 exports, unchanged」；
4. 而那个正是我想验证的结论 —— **“基线与 HEAD 一致，所以没被改写”**。

**发现方式**：`git status` 里 `task-position.ts` 仍是 `M`，而我只改过 `index.ts`。
修正方式是 `git checkout --` 回到 HEAD 后重做，之后每次重建都确认 `git status` 干净、
且产物字节数与提交逐字节一致。

**纪律**：临时备份名必须含**原文件名**（`index.ts.bak`，而不是 `gidx.ts.bak`）；
恢复前把「来源路径」与「目标路径」并排打印一次再执行。
**备份名一旦抹掉身份，恢复就是一次盲写。**

## 3. `author.sessionId` 写错一个字 ⇒ 审计查不到人

**事实**：给任务图写节点更新时，我把 `auto-graft-mwllk1wh-k8mmu5` 打成了
`auto-graft-mwllh1wh-k8mmu5`（`k` → `h`）。

**为什么这条不是小事**：`origin.by` / `history.author` 的全部价值是**能回答「谁改的」**。
一个错字的 id 在审计时**查不到任何人**，而它看起来完全正常——所以它不会在任何门禁上变红，
只会让「可追溯」这个承诺悄悄失效。

**当时的处理**：`history` 只追加不改写（T1c 已定），所以追加了一条更正条目，
理由写「更正上一笔的 sessionId 笔误，审计时按本条为准」。

**纪律**：sessionId 一律从环境变量 / 日志里**复制**，不手打；写完后回读一次与来源逐字比对。
