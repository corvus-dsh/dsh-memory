# 检索规模基准（W4-3）

> **这是一份基线，不是门禁。** 记录读数与测量方法；阈值由 `--check-warm` / `--check-cold` 显式给出，
> 且默认不设。

## 一、为什么要这份文件

审计 AUD-14：检索路径**没有规模基准**。仓库里流传的「2000 条 2.5 ms」只出现在一份报告里，
手工测得一次、机器不明 —— 这与 W4-1b 里「四仓逐字节相同」是同一个处境：
**一个数字，只有一个来源，没有任何东西能复算它。**

复算方式：

```
npm run baseline:retrieval              # 默认 7 次采样
npm run baseline:retrieval -- --samples 5
npm run baseline:retrieval -- --check-warm 2     # 派工单判据
npm run baseline:retrieval -- --check-cold 1000  # 扫描路径
```

脚本：`scripts/retrieval-baseline.mjs`；判据：`test/v283-retrieval-scale-baseline.test.mjs`（6 条）。

## 二、读数（2026-11-20，本机）

环境：`node v24.21.0` · `win32 x64` · 5 次采样 · 取中位 · 机器无其它 job。

| 语料条数 | warm (ms) | cold (ms) | 实际解析 |
|---|---|---|---|
| 50 | 0.03 | 7.1 | 50 |
| 200 | 0.02 | 26.2 | 200 |
| 800 | 0.02 | 87.2 | 800 |
| 2000 | 0.02 | 207.0 | 2000 |

再跑一次（`--samples 5`）：2000 条 warm 0.03 ms / cold 258 ms。**cold 的绝对值在 ±25% 内浮动，warm 稳定。**

## 三、两个数字分别是什么，以及为什么必须分开

| | 含义 | 随语料规模 |
|---|---|---|
| **warm** | 进程已运行、`skill-cache.ts` 命中（键是目录 mtime） | **不变**（0.02–0.03 ms） |
| **cold** | 每份 `SKILL.md` 真的被读取并解析 | **近似线性**（7 → 207 ms） |

**这道区分是本节最重要的一条**，因为脚本第一版只报 warm，得出「2000 条 0.02 ms」——
真话，但几乎没有信息量，而且它会被原样抄进报告。

第一版的 `--cold` 还是无效的：它调 `invalidateDocuments`（文档缓存），而这个路径读的是
**skill 文档缓存**。于是「冷」跑其实在测缓存命中，2000 条与 50 条一样快。

> **can-red 证据**：把 `invalidateSkillDocs` 换回 `invalidateDocuments` ⇒
> `v283 ①` 红，报「2000 条的 cold 必须至少是 50 条的 5 倍；实际 0.06 vs 0.05（比值 1.2）」。

## 四、派工单判据

| 判据 | 实测 | 结论 |
|---|---|---|
| 2000 条 **warm** ≤ 2 ms | 0.02–0.03 ms | **达标**（有大量余量） |

派工单原话是「2000 条 warm ≤ 2 ms（现有实测 2.5 ms，钉住即可，不许抬高）」。
实测远低于 2.5 ms，所以这条判据现在钉在一个**真实且宽松的**位置上。

**没有 cold 判据**，因为 cold 的合理上限取决于语料真实规模；`--check-cold` 存在，供将来设定。

## 五、已知限制（说清楚，不假装没有）

1. **语料是合成的**：50/200/800/2000 份生成的 `SKILL.md`，字段结构真实、词汇是循环生成的。
   真实语料的词频分布不同，**tokenise 与打分的成本可能与合成语料不同**。
2. **只测了 `skillDocuments`**：这是检索路径里规模敏感的那一段（读 + 解析 + 建文档）。
   打分与排序（`retrieve`）未纳入本基准，因为它的成本取决于**查询**而非**语料规模**，
   需要另一种基准（查询集固定、语料变化），尚未做。
3. **单机**：`win32 x64` 的 `statSync` 与 `readFileSync` 成本不代表 Linux CI。
   跨平台对比未做 —— 若要，须在 CI 上跑同一脚本并分别记录，不许混在一张表里取中位。
